# 교육다함 v54 — 3단계 권한 및 부서별 접근

## 배포
GitHub 저장소에 ZIP 전체 내용(index.html, api, vercel.json)을 업로드하고 Vercel에서 재배포합니다. 기존 Notion 데이터는 지우지 않습니다.

Vercel 환경변수:
- `NOTION_TOKEN`: Notion 통합 비밀키
- `NOTION_DATABASE_ID`: Notion DB ID (Name 제목, Payload 텍스트 속성 필요)
- `ADMIN_ACCESS_TOKEN`: 전체 관리자 비밀키

## 사용자 접속
- 전체 관리자: 메인 페이지에서 `ADMIN_ACCESS_TOKEN`을 입력 → 전체 부서 조회 및 부서 선택.
- 부서 서무: 부서원 관리에서 `서무주사`로 지정된 직원의 `링크 발급` 버튼으로 생성된 개인 링크 접속 → 자신의 부서만 관리.
- 일반 부서원: 동일한 `링크 발급` 기능으로 받은 개인 링크 접속 → 자신의 교육만 조회·수료 처리.
- 개인 링크는 URL fragment(`#access=...`)를 사용하며 최초 접속 시 주소창에서 제거됩니다. 브라우저 탭의 sessionStorage에 보관하므로 브라우저를 완전히 닫으면 재접속 시 개인 링크가 필요할 수 있습니다.
- 부서별 비밀번호, 직원이 직접 선택하는 권한, 행정번호만으로 로그인하는 기능은 제공하지 않습니다.

## 구현한 권한 제한
- `admin`: 전체 데이터 및 선택 부서 관리. 부서 선택 시 해당 부서의 직원/교육/배정만 API로 반환.
- `clerk`: 해당 부서 직원·교육·배정만 API로 반환하며, 서버에서 다른 부서에 대한 변경을 거부.
- `employee`: 본인 직원정보·배정 교육만 반환, 본인 수료상태만 변경.
- 인사이동은 전체 관리자가 전체 부서 화면에서 처리해야 합니다. 부서 서무가 타 부서로 직원을 이동시키는 것은 서버에서 거부합니다. 중복 행정번호도 서버에서 검증합니다.
- 서무 권한은 `isClerk` 체크박스를 기준으로 요청마다 재확인합니다. 같은 부서 복수 서무 지원.

## 주의 및 제한
- 직원 개인 링크는 소유자가 본인이라는 강한 신원확인이 아닌 **소지자 인증**입니다. 링크 유출 시 타인 접속 가능하므로 비공개 전달·재발급 정책이 필요합니다.
- 전체 관리자 비밀키를 부서 서무에게 공유하지 마세요.
- 기존 Notion 단일 레코드 방식은 동시 편집 충돌 및 저장 용량 한계가 있습니다. 여러 부서 실운영 전 별도 DB 구조와 원자적 업데이트가 필요합니다.
- Notion 최신 API와 호환성은 실제 배포 환경에서 확인해야 합니다.
- 공문 원본은 브라우저별 저장으로, 다른 PC에 자동 공유되지 않습니다.
- 테스트 전 기존 DB 백업을 권장합니다. 실브라우저/Vercel/Notion 통합 테스트는 미수행입니다.

## v55 권한 변경
- 전체 관리자: 시스템 관리 탭에서 부서별 서무 지정·해제, 개인 접속 링크 발급 및 부서 화면 전환.
- 부서 서무: 소속 부서 직원 신규 등록·수정·팀 이동·타 부서 인사이동 가능. 타 부서 직원의 직접 수정 및 타 부서 직원 신규 중복 등록 차단.
- 인사이동: `인사이동` 열에 목적 부서명 입력 후 저장. 기존 직원 ID와 이수기록 보존, 서무권한 해제, 개인 접속 링크 무효화. 목적 부서의 전체 대상 교육에 자동 배정.
- 부서 서무의 서무 권한 변경 및 접속 링크 변경은 서버에서 거부. 서무 본인의 인사이동은 전체 관리자에게 요청.
- 주의: 기존 Notion 단일 레코드의 동시 저장 충돌 가능성은 남아 있습니다. 실제 여러 부서 동시 운영 전에 데이터베이스 분리 및 충돌 방지가 필요합니다.


## v56 권한 변경
- 전체 관리자: 시스템 관리, 로그인 링크 발급 및 부서 운영현황 조회.
- 부서 서무: 소속 부서 직원 신규 등록·수정·인사이동 및 복수 서무 지정·해제 가능.
- 부서 서무는 다른 부서의 직원을 수정하거나 로그인 토큰을 변경할 수 없음.
- 마지막 재직 서무의 권한 해제는 차단. 본인 서무 계정의 타 부서 인사이동은 다른 서무 또는 전체 관리자에게 요청.
- 현재 단일 Notion 레코드 저장 방식은 동시 편집 충돌 위험이 있으며 실제 서버 통합테스트는 수행되지 않음.


## v57: 부서 서무 로그인 링크 관리
- 부서 서무는 본인 소속 부서의 직원 개인 링크를 발급, 기존 링크 복사, 재발급(기존 링크 무효화), 폐기할 수 있습니다.
- 신규 API `api/link.js`에서 인증된 직원의 소속 부서를 서버에서 확인합니다. 일반 직원 및 다른 부서 서무의 링크 관리 요청은 거부합니다.
- 서무에게 내려주는 직원 목록에는 로그인 토큰 원문을 포함하지 않습니다. 발급 시에만 서버가 해당 토큰을 반환합니다.
- 새 직원은 먼저 부서원 관리에서 저장한 후 링크를 발급합니다.
- 기존 Notion 단일 레코드 동시 저장 충돌 및 개인 링크의 전달·유출 위험은 여전히 존재합니다.

## v58: 전체 관리자 최초 부서 및 서무 등록
1. 전체 관리자로 로그인 → **시스템 관리** → 상위 조직(국) 및 실·과명 입력 → 부서 저장.
2. 같은 화면의 **최초 서무주사 등록**에서 부서, 팀, 성명, 행정번호, 직급 입력 → 서무주사 등록.
3. **서무주사 접속 링크** 표에서 링크 발급 → 복사한 URL을 해당 서무에게 전달.
4. 서무는 본인의 링크로 접속 → **부서원 관리**에서 직원 추가, 서무 지정, 직원 링크 발급 → 직원은 개인 링크로 로그인.
5. 부서명을 수정하면 기존 직원·교육의 소속 부서명도 함께 변경됩니다. 다른 부서에 이미 등록된 행정번호는 중복 등록하지 않습니다.

서버 데이터는 기존 Notion DB의 단일 Payload JSON 안에 `departments` 배열로 추가 저장합니다. 별도의 Notion 속성 추가는 필요하지 않습니다. 전체 관리자가 처음 저장하면 생성됩니다. 기존 데이터는 유지됩니다.

주의: 실제 배포 전 테스트가 필요합니다. Notion 단일 rich_text 속성은 용량 제한이 있어 직원과 교육 데이터가 커지면 별도 테이블로 이관해야 합니다. 관리자 접근키와 개인 링크는 외부에 공유하지 마세요.
